# Oz Box 0.3.0-beta.1

Released 18 November 2026. Install with `sh install.sh --version 0.3.0-beta.1`, then `ozbox upgrade <box>` for each box. The full list
is in the [changelog](../../docs-site/changelog/index.mdx); this page is the short version.

## Highlights

- **Safer approvals.** Imports, declarations and tunnel tokens are approved in the dashboard while the command waits, with no code to
  copy. Production is approved in the dashboard only; a key kept on your computer can no longer approve it.
- **Agents cannot read your sign-in factors.** On every box, agents can no longer read, replace or list your authenticator secret, the
  Google sign-in secret or your devices' notification keys.
- **Upgrades that keep your things.** A new system disk is tagged at once, ordinary project repositories are saved, the dashboard comes back
  after an upgrade, and the report says how to pin a new secrets store's key.
- **Smaller first-start data** for a new box, with room to grow within each provider's limit.
- **Node commands reach their declared hosts** with `ozbox env run` (Node 22.21 and 24.5 onward).
- **Copy and paste work** in the browser IDE, the dashboard's terminal and the desktop.
- **Talk to a box, a session or the fleet from Telegram**, and start or pause boxes from your phone inside limits you set.
- **Messages and alerts open exactly what they are about**, and read the same on every channel.
- **OpenBao, SES and SNS from a box** work without the `aws` or `bao` programs; arm boxes are offered arm images.
- **`ozbox init`** previews every step, checks quotas first and cleans up after a failed step.

## Preview in this release

These are built and tested but not yet run on a real box or with a real service, and may change:

- approving in the dashboard while a command waits (passkey and authenticator paths);
- Codex on a ChatGPT plan, and the plan-by-plan view in Settings, Models;
- Telegram control, including box power from a phone;
- task channels between your computer and a box, and `main` handing a task to a worker;
- the first part of managing your fleet from a box's own dashboard (built, not turned on).

## Upgrade notes

- **First boot changed.** A box's first boot now takes more of its setup scripts from the `ozbox` program the box already has. On AWS,
  `ozbox upgrade` of a box made by an older version replaces its machine from the current first boot; `/work` is kept. Read the plan
  before you confirm it.
- **A system disk made by an older version** needs tagging once by an account administrator before the pre-upgrade copy works. The refusal
  gives the exact command, or pass `--no-pre-upgrade-snapshot`.
- **Authenticator apps set up before this release:** treat them as possibly seen. On the dashboard's Account page choose **Remove** under
  **Authenticator app**, then set one up again (add a passkey first if the authenticator is your only second factor). On a box not yet
  upgraded, the authenticator, Google sign-in and device notifications stop working until you upgrade it.
- **Production imports** take the dashboard's approval; a code from your computer's key is refused.
- **Tunnel tokens:** if an old tunnel is still running as the box user, run `ozbox dashboard retire-legacy-tunnel <box>` and rotate the token.
- **Image publishers:** older image versions are now kept private by default.
- The program and the box must share the same minor version; upgrade both.

## Known limits

- Older Node, Python `aiohttp` without `trust_env=True`, and Java do not read the proxy variables, so their https calls still fail.
- Claude plans, Google accounts and Aider cannot be used in place of a key; the vendors' terms do not allow it.
- Setting a tunnel token from the box itself, removing one, placing a vault token and a host guard change still take a code.
- A box's dashboard still says the fleet is not connected.
