Finance work is repetitive, deadline-driven and sensitive. An Oz Box gives an AI agent a place to do the repetitive part
(reconciling, extracting, checking, drafting) inside your own cloud account, with your figures never leaving it if you use a
local model, and with every action recorded.

See [how to read the status](/use-cases#how-to-read-the-status). Everything here is **Preview** at most: built and tested, not
yet run end to end by a finance team on a real box.

**Ground rules for every example:**
- **The agent never moves money.** It prepares; a person pays, files and signs.
- **It is not financial advice.** It reconciles, extracts and drafts; judgements and decisions are yours.
- **Keys stay out of reach.** Bank, accounting and payment credentials are used through declared commands with keys the agent
  cannot read; Production credentials need an approved session ([a secure workspace](/use-cases/secure-agent-workspace)).
- **Everything is auditable.** Every file read, command and approval is in a log that shows if it was edited.

## 1. Month-end close helper

**You want:** the bank export and the accounting ledger compared, with only the mismatches listed.

Put both exports on the box (or let a declared command fetch them), then ask: *"Reconcile /work/close/2026-10, list unmatched
items with amounts and dates."*

**Underneath:** a supervised run with a time and spend cap; the result is a table of exceptions saved on the box.
**Limits:** the agent matches what it is given; a person reviews and posts any adjustment.
**Status:** Preview.

## 2. Invoice processing

**You want:** supplier invoices (PDF or email) read, with vendor, date, amount, tax and due date extracted, ready for entry.

```
ozbox schedule add --name invoices --when "every weekday at 6pm" --engine claude-code --box finance \
  --prompt "Extract new invoices in /work/inbox/invoices into the entry sheet; flag duplicates" --results-to alert
```

**Underneath:** the extracted fields go to a sheet; nothing is posted to your ledger without your approval.
**Limits:** scanned or handwritten invoices may be misread; each row links to its source file.
**Status:** Preview.

## 3. Expense review against policy

**You want:** receipts checked against your expense policy, with exceptions flagged for a person.

Give the agent your written policy (as an approved skill or a memory note) and the month's receipts.

**Underneath:** a run that writes an exceptions list with the policy line each one breaks.
**Limits:** flags only; approval and reimbursement stay with your team.
**Status:** Preview.

## 4. Weekly cash-flow forecast refresh

**You want:** your forecast spreadsheet updated each week from the latest figures, with a short note on what moved.

```
ozbox schedule add --name cashflow --when "every monday at 7am" --engine claude-code --box finance \
  --prompt "Update the forecast in /work/forecast.xlsx from this week's exports; note the three biggest changes"
```

**Underneath:** the agent edits a copy and keeps the previous version; you compare before adopting it.
**Limits:** the model of your business is yours; the agent updates inputs, it does not invent assumptions.
**Status:** Preview.

## 5. Board and investor packs

**You want:** a first draft of the monthly or quarterly pack from your numbers and last quarter's narrative.

Ask from chat with the files in place: *"Draft the Q3 board pack from /work/board using last quarter's structure."*

**Underneath:** a supervised run following an approved skill for your pack's structure; the draft is saved for review.
**Limits:** numbers are copied from your sources with references; commentary is a draft for you to rewrite.
**Status:** Preview.

## 6. Audit preparation

**You want:** the documents an auditor requested gathered into one folder with an index.

Give the agent the request list; it finds the files on the box and builds the index.

**Underneath:** the audit trail shows exactly which files the agent opened, which helps when you are asked how the pack was
put together.
**Limits:** it can only gather what is on the box or reachable through your declared connectors.
**Status:** Preview.

## 7. Vendor payment run preparation

**You want:** the payment list for this week built and checked for duplicates and changed bank details.

**Underneath:** the agent prepares the list and flags anything unusual (a new account number, a duplicate invoice).
**Limits:** **the agent never pays.** The list is for a person to review and pay through your bank.
**Status:** Preview.

## 8. Budget versus actual commentary

**You want:** plain-language explanations of the biggest variances, per department.

**Underneath:** a run reads the budget and the actuals, writes short notes per line, and names the source of each figure.
**Limits:** it explains the numbers; it does not know the business reasons unless you tell it.
**Status:** Preview.

## 9. Filing and deadline calendar

**You want:** every tax and regulatory deadline tracked, with a checklist prepared ahead of each.

Add the deadlines as memory notes, then schedule a weekly reminder that prepares the checklist for anything due soon.

**Underneath:** reminders arrive on your alert channels; checklists are saved on the box.
**Limits:** **nothing is filed by the agent.** Check deadlines against your regulator's official calendar.
**Status:** Preview.

## 10. Sensitive figures on a model in your own account

**You want:** finance work where the numbers never go to an outside AI service.

Run a local model on the box (Settings → Models → Set up Ollama on any box, or `ozbox models` to choose it for an engine) and
point the finance runs at it.

**Underneath:** the model runs on your box; the run's model calls stay inside your account.
**Limits:** a local model on a CPU box is slower and less capable than a large hosted model; choose a box size that fits.
**Status:** Preview (local models have not been run on a real box yet).
