# Oz Box documentation site

The source for the Oz Box documentation site, built with [Mintlify](https://mintlify.com). Nothing here is connected to a
hosting account or a domain yet; the steps to do that are at the bottom.

## How it is built

There is one source for the guides: `docs/` (and `SECURITY.md`, `ROADMAP.md`). A script turns it into the site, so the
repository and the site cannot disagree.

| Source | Becomes |
|---|---|
| `docs/use-cases/*.md` | `use-cases/*.mdx` (the folder's `README.md` becomes the section index) |
| `docs/adr/*.md` | `adr/*.mdx` (with an index page) |
| `docs/<name>.md` (architecture, and any guide added later) | `<name>.mdx` |
| `SECURITY.md`, `ROADMAP.md` | `security-policy.mdx`, `roadmap.mdx` |
| `docs.base.json` + the pages above | `docs.json` (the navigation is generated) |

The pages written by hand are `index.mdx`, `install.mdx`, `cli-reference.mdx` and `changelog/index.mdx`. Everything else
in this folder that carries a `GENERATED by` line is output: **do not edit it, edit the source in `docs/`**.

**The generated pages are committed**, because Mintlify reads a folder of a repository and a person can then read exactly
what will be published. To keep them honest, CI runs `build-site --check`, which fails when any generated file is missing,
out of date or stale. After changing anything in `docs/`:

```bash
cd docs-site
npm ci          # once
npm run build   # regenerate pages and docs.json; commit the result
```

A new `docs/<name>.md` needs no change to the scripts: it appears in the navigation. `docs.base.json` says which group
it lands in (`placement`); an unlisted guide goes to **Guides**. Group order and the hand-written pages are also in that file.

The conversion escapes what MDX cannot take in prose (braces, a bare `<`), removes HTML comments, turns links between
guides into site links, and turns links to other repository files into GitHub links. A link to a file that does not exist
fails the build.

## Checks

```bash
npm test          # unit tests of the scripts (node --test)
npm run check     # generated pages in sync, validate, compile, offline link check
npm run validate  # navigation both ways, front matter, no HTML comments, no private names, links and anchors
npm run compile   # compiles every page with the same MDX compiler the hosted build uses
npm run links     # offline link, anchor and image check (the hard gate; no network)
```

`mint dev` is not the hosted build and accepts pages the hosted build rejects, which is why `compile` and `validate`
exist. CI (`.github/workflows/docs-site.yml`) also runs `mint broken-links` as an informational extra step, because it needs
the network; the offline check is the one that blocks.

Entries in `changelog/index.mdx` are dated `[Release date]` while the work is built, and keep it after they merge into `main`
until the release that ships them: the date a reader sees is the day the change shipped, not the day it merged. A real release
refuses any left over (`.github/workflows/cli-release.yml`), so right before tagging run:

```bash
npm run stamp-release                          # today
npm run stamp-release -- --date "November 10, 2026"
```

## Preview

```bash
npm run dev     # runs `mint dev` (pinned version, fetched by npx) at http://localhost:3000
```

## Owner steps to publish (nothing is connected yet)

1. Create a Mintlify project from this repository. In the dashboard choose the GitHub repository and set the
   **docs folder** to `docs-site` (the folder that holds `docs.json`). The default branch deploys on every push.
2. Add the custom domain `docs.ozbox.dev` in the Mintlify dashboard (the owner registers `ozbox.dev` first) and create the DNS
   record Mintlify shows. Until then the project has only Mintlify's own address; nothing in this folder assumes the domain, so
   it is a dashboard setting and not a code change.
3. Optionally add a repository secret if you later want CI to trigger a deploy. The hosted GitHub connection needs none.
4. Before the first public release, run `npm run stamp-release` so no `[Release date]` placeholder is published.
