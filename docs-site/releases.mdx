## One version

The program, the box daemon and the machine image share one version, `MAJOR.MINOR.PATCH` ([ADR 0036](/adr/0036-one-version-for-the-program-the-daemon-and-the-image)).
Before 1.0 a minor version may break anything and a patch never does. A version with a suffix, such as the Beta `0.2.0-beta.0`, is a pre-release: GitHub Releases marks it as one, and the installer's "latest" skips it, so name the version (`sh install.sh --version 0.2.0-beta.0`).

## Cadence

- A **minor release every month**, with a changelog entry and a new machine image of the same version.
- **Patch releases whenever needed** (a fix, a security update), each with a changelog entry and a new image.
- Dates are targets, not promises; a release waits for its tests and its signed build.

## Which releases are supported

| Release | What it gets |
|---|---|
| The **latest minor** (for example 0.4) | features and fixes |
| The **previous minor** (0.3) | **security patches for three months** after the next minor ships |
| Anything older | nothing: upgrade |

A program and an image must share the major and minor version, so `ozbox upgrade` moves a box one supported step at a time: it
refuses an image from a different minor version and says which side to upgrade, and the message names the supported releases.
A patch version is always safe to take.

## Where the images come from (Preview)

The machine images are built and published by the image workflow, from a dedicated AWS account, as public images in `us-east-1`,
`eu-west-1` and `ap-southeast-1` for both architectures; the last three released versions stay public and older ones are
retired after a successful release ([ADR 0052](/adr/0052-public-images-from-one-account-trusted-by-owner-and-signed-manifest)).
`ozbox create` with no image named, and `ozbox upgrade`, use the newest Oz image in your own account if there is one, and
otherwise the newest public one that the publisher account owns and the release's signed manifest lists. Nothing else is
accepted: an image from another account, or one the signed manifest does not list, is refused with the reason.

The workflow's two AWS-signing jobs (the build and the publish job) run in the GitHub environment **`image`**, whose required
reviewer approves a release; the build role trusts that environment alone. This is Preview until the first public release has
been built and a clean account has created a box from it.

## Support

- **Community support** is free and best effort: [GitHub Discussions](https://github.com/OzboxHQ/ozbox/discussions) for questions
  and ideas, and issues for bugs. Please never post keys, tokens or private data.
- **Paid support plans** are available from the company behind the project. Open a
  [GitHub Discussion](https://github.com/OzboxHQ/ozbox/discussions) (once enabled) or an issue asking for it, and do not
  put anything private in it.

Security problems follow [SECURITY.md](/security-policy), not the public channels.
