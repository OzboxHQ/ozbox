**Decision.** A supervised run (ADR 0014) on a real box is carried out by the box daemon, reached over the same outbound
route as every other call. Nothing new listens on the box.

1. **The daemon runs it, the dashboard server watches it.** The Claude Code adapter asks the daemon's run API to start the
   agent in its own cgroup (so memory admission and the wall-clock limit are the daemon's), reads its output back in whole
   lines from a byte offset, and stops it. A checkpoint is the daemon's existing one: uncommitted work goes to a `wip/` branch,
   and the branch it names is what a paused run resumes from. A dropped connection to the box is tolerated for a while (a
   run that is already going keeps going on the box); a box that cannot be reached keeps a queued run waiting, with the
   reason, instead of failing it.
2. **The prompt is the run's standard input.** It travels in the request body and the daemon feeds it to the program
   through a pipe and keeps no copy: not an argument (`ps` lists those) and not a file. Its length is limited to what one
   request holds.
3. **The run gets a per-run token and an address, never a provider key (ADR 0017).** The broker runs inside `ozbox serve`, on
   the operator's computer. When a run's environment names the broker's port, the server opens an `ssh -R
   127.0.0.1:&lt;port>:127.0.0.1:&lt;port>` over the connection it already uses to reach that box, so the same port answers on
   the box's own loopback and the run's base address works unchanged. Both ends are spelled `127.0.0.1`: no wildcard, no
   dependence on `GatewayPorts`, and no port open to anything but the box itself (ADR 0005). If the port is taken on the
   box, the forward fails at once and the run waits with that reason. The forward closes when it has not been used for a
   few minutes.
4. **The daemon's cap follows the box's size.** The box's first-boot configuration sets the daemon's `runs.max_active` to the
   size's cap (XS 1, S 2, M 4, L 6, XL 8, XXL 16, GPU-S 4, GPU-L 8), the same table the supervisor applies. A box made bigger later
   keeps its first number until it is made again; the supervisor's cap follows the size at once.
5. **Local models are a service of the box user.** Ollama or vLLM runs as a `systemd --user` service of the box user (kept
   running by linger) bound to the box's loopback address. The daemon writes its unit, starts and stops it, and talks to it
   over the loopback; a download is a background job with progress, because a model is gigabytes and no request waits for it.
   Because the daemon must reach the box user's service manager under `/run/user`, its unit sets `ProtectHome=read-only`
   instead of `true`.

**Why.** The two ways this could have gone wrong are a key that reaches the box and a port that opens on it. A token worth one
run, delivered through a forward that only the box can use, avoids both, and putting the run in the daemon's cgroup means a
runaway agent is stopped by the same limits as every other run.

**Costs.** One more SSH session per box while runs are active. The prompt limit (about 40,000 bytes) is lower than the
dashboard's 20,000 characters for text that is mostly multi-byte. A box on an image from before this change has no log
endpoint, so its runs wait and say the box's agent is too old (`ozbox upgrade`).
