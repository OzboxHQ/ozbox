**Decision.** A box's web IDE (code-server) and desktop (KasmVNC) run as `systemd --user` services of the box user, bound to
`127.0.0.1`, with their own sign-in on. Nothing opens on the box (ADR 0005, ADR 0011: the box user has no sudo, so the
services are the box user's own). Three ways in, one command or one click each:

1. **On `localhost`.** `ozbox ide <box>` and `ozbox desktop <box>` forward the box's loopback port over the SSH route the
   program already uses, and listen on `127.0.0.1` of this computer. A dropped forward is rebuilt by the next connection and
   by a keep-warm check. The service's password is generated here, kept write-only in the secret store, and reaches the
   browser only through a one-time address answered by this program itself (a sign-in form for code-server, a redirect for
   KasmVNC), never a command line or a long-lived URL.
2. **On your own address.** `ozbox ide <box> --public-url https://ide.example.com --tunnel cloudflare|caddy`, or the switch on
   the box page. A request for that host reaches the box only with an Oz Box session behind it. The dashboard's session cookie
   is never widened to the new host; a signed-in person trades it for a single-use 60-second ticket, and the code host gives
   a cookie of its own that stops working when the dashboard session it came from ends. Without it, nothing is dialled: not a
   page, not a WebSocket upgrade. An identity-aware proxy in front of the tunnel is therefore one lock, never the only one.
   The listener is its own (`--code-port`), so WebSockets are relayed byte for byte. Only tunnels that can carry a second
   host name qualify (Cloudflare, Caddy); the others say so.
3. **From a desktop editor over SSH.** `ozbox open <box> --in <editor>` refreshes the SSH entry and opens the editor's link,
   only where the editor documents one; forks that do not are marked unverified.

Work started through any of them is **not lost by disconnecting**. Editor terminals open in tmux (`oz-term` reattaches to
the first unattached `term-N` or makes one), the editor restores windows and terminals, code-server keeps a week of
reconnection, and the services start again after a reboot. `ozbox ps <box>` and the box page list what is running (tmux
sessions, coding agents, listening servers) and stop one on request, planned and confirmed.

**Why.** People expect "open my box in a browser" to be one step, and expect their running agents and servers to still be
there when they come back. Doing it outbound-only and with a lock of our own keeps the project free of anything we would have
to run or trust, and of a single point of failure in somebody else's access rules.

**Cost.** tmux sessions end when the machine restarts, and the box page and `ozbox ps` say so; a service that must outlive
that belongs in a unit, and a coding agent in its checkpoint. The box user's services need `loginctl enable-linger` set at
first boot; until the image does that, setting the services up is refused with the exact fix. The IDE address is served by
the machine running `ozbox serve`, not by the box, so that machine must be up.

## Addendum: reading and stopping what runs, and the tunnel on the box

- The box daemon answers `GET /v1/sessions` (tmux sessions) and `GET /v1/processes` (the box user's coding agents and listening
  dev servers), and stops one with `POST /v1/sessions/<name>/stop` or `POST /v1/processes/<pid>/stop`. Everything is an argv
  array, only the box user's own processes are listed, and a stop is checked against a fresh read, so a name or number typed by
  hand cannot stop anything else. The command line and the dashboard use these first and fall back to the fixed SSH script when
  the daemon is unreachable or older. The daemon has no private `/tmp`, so it sees the same tmux server as the box user's SSH and
  editor terminals; the web terminal's Open attaches one named session.
- A Cloudflare tunnel may run on the box itself (`ozbox tunnel setup cloudflare --on-box <box>`, or the Code panel) as a
  `systemd --user` service. The token travels on standard input, is kept in a 0600 file under the box user's home, and is never in
  a unit, an argument, a plan or an answer. Pointed straight at the IDE it is protected by the IDE's own password only; the
  Oz Box sign-in is in front only when the tunnel runs where the dashboard runs.
