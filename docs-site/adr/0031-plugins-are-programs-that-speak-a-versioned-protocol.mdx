**Decision.** A provider or a tunnel can be added without changing Oz Box: a plugin is a separate program that speaks
JSON-RPC 2.0 over standard input and output, one message per line (the way language servers and MCP servers do). The contract is versioned (`api_version`, now `1`),
documented in `docs/plugins.md`, and implemented by the `ozbox-plugin` crate (types, helpers for authors, and the host side).

- **A separate process, started by Oz Box for each call.** A plugin may be written in any language, can crash or hang
  without harming Oz Box (every wait has a limit and a late plugin is killed), and holds state in files of its own. A call is
  `initialize` (the version handshake) and then one request.
- **Approved by hash, like skills (ADR 0025).** A plugin is a folder with `plugin.toml` (name, kind, api version, program).
  `ozbox plugin add` shows the manifest and the program's SHA-256; nothing runs until `ozbox plugin approve` records that hash,
  and a changed program is not run until it is approved again.
- **Providers go through the provider interface (ADR 0003).** A provider plugin is wrapped as an `ozbox_core::Backend` and the
  shared engine plans, confirms and fences it like a built-in; the same conformance suite that the built-in providers pass runs
  against the example plugin.
- **Secrets are not arguments.** Requests are standard input; a plugin's environment is empty apart from `PATH`, and the host
  never passes a stored key unless a request type says so.
- **Built-ins do not change.** `fake`, `hcloud`, `aws` and the five tunnels are untouched; the protocol is additive within a
  version and a breaking change is a new `api_version` that the host runs side by side.

**Why.** A closed set of providers limits who can use the tool, and a plugin that runs in-process (a dynamic library) would run
with the person's full authority and break on every compiler change. A process and a hash is the smallest thing that is safe
enough and easy to write.

**Cost.** Each call starts a process. A plugin runs with the person's privileges, which is why it needs approval by hash and
why the host trusts nothing it returns (answers are checked and sizes are capped). Selecting a plugin provider is a
configuration choice; some features that need a provider's prices or API (the real-bill view, forgotten-resource listing) are not
available for a plugin.
